## 核心模型：形态、任务与上下文分离

| 维度 | 状态 | 作用 |
| --- | --- | --- |
| 窗口形态 | Collapsed / Preview / Engaged / Pinned | 决定尺寸、焦点、是否可操作、窗口排列。 |
| 任务 | idle / working / waiting / failed | 来自 runtime 事件，只改变状态指示与内容，不偷偷改变窗口形态。 |
| 上下文 | 未采集 / 待发送附件 / 已绑定工作目录 / 覆盖或过期 | 决定来源提示和可用操作，不把「并排布局」误称为工作目录。 |

### 四个窗口状态

| 状态 | 进入与退出 | 焦点、采集、布局、内容 |
| --- | --- | --- |
| **Collapsed** | 默认；离开 Preview 的短暂宽限后回到此状态；显式关闭 Engaged/Pinned 也回到此状态。 | 右侧中部的窄竖胶囊。只显示 Aside 标记和任务/待决状态；不因悬停采集或启动任务。若已有任务正在运行，收起界面不得终止任务，胶囊继续显示状态。 |
| **Preview** | 指针在窄触发走廊停留后展开；离开后经宽限收起。 | 全高只读预览，不夺取焦点、不移动前台窗口、不自动采集当前窗口。展示近期会话概况、当前运行/待决状态；敏感路径和权限细节等点击后再展示。 |
| **Engaged** | 点击预览/胶囊进入；先在原生层锁定前台目标，再激活窗口和输入框。 | 可输入、可采集、可处理权限。仅当前台窗口与 Aside 冲突时按既有恢复逻辑并排；关闭时恢复原窗口。 |
| **Pinned** | Engaged 内显式固定；全局快捷键从收起状态直接展开并固定。 | 与 Engaged 同一界面，指针离开不收起。再次按快捷键或显式关闭回到 Collapsed。 |

保留 WinIsland 的窄触发走廊、停留与离开宽限、固定锚点和非激活预览；停留与动画时长先以原型参数为起点，再由自动化状态测试约束边界。Preview 到 Engaged 的点击焦点是原生可行性门槛。`Esc` 先关闭附件详情/权限详情，再关闭面板；**Stop** 才取消运行，收起面板不取消任务。权限超时仍由 runtime 管理。

WinIsland 草图中的「悬停就知道当前文件并提出问题」不照搬：Aside 的上下文是明确采集的有时效引用。悬停不能悄悄触发 UIA 采集，也不能把上一次的附件冒充当前窗口。快捷键或点击时先记录前台目标再取得焦点，沿用现有一次性采集语义。

## 展开后的信息架构

```text
Aside · 当前状态                         [固定] [收起]
当前来源 / 已绑定工作目录                [查看或更换]
──────────────────────────────────────────────
对话正文
  消息
  相关工具步骤（可展开）/ 外部程序标识
  局部读取、文档质量、输出验证与错误
──────────────────────────────────────────────
待发送来源：文件/网页/窗口摘要、有效期     [移除]
[采集当前窗口] [输入消息                 ] [发送/停止]
```

1. **顶部是任务定位，不是仪表盘。** Aside 标记、运行状态、Pin/收起；第二行只显示当前来源和工作目录。原生「并排布局」与 runtime 的「工作目录」用不同名称和入口。无目录时保留现有手动指定作为恢复路径。
2. **附件贴近输入框。** 采集后显示来源、类型、摘要和到期状态，用户可移除或打开详细 JSON；提交当前提示后按现有规则清空待发送附件。路径用短名排版，完整路径在详情内可查看，不因截断丢失身份。
3. **工具与文档状态跟随相关消息。** 普通调用是紧凑的一行进度；展开可看受界限约束的结果。MCP 明确标记「Outside Aside」和服务器来源；PDF 的部分提取、Word 的来源保真警告、输出重新打开验证分别呈现，不能统称成功。
4. **权限是唯一强打断层。** 需要决策时在输入区上方放高对比度决策面板，明确操作、工作目录、目标、受限预览、外部边界与到期时间，默认清晰呈现 Deny 和单次 Allow。现有 broker 已发送 `explanation`、`workspace`、`targets`、`preview`，当前 React 类型和卡片没有完整消费；这里只扩展展示，不改变授权规则。Preview 只显示「需要你确认」，点击 Engaged 后才展示细节和按钮。
5. **错误和覆盖不消失。** 捕获目标被显式选择覆盖、MCP 没提供工具、目标过期、权限被拒绝等状态留在相关任务内；状态胶囊只提供提示，不以颜色替代文字说明。

不添加虚假的「新会话」「设置」「启用服务器」按钮，因为现有产品没有对应操作。旧计划中的功能候选继续留在 backlog。

## 视觉语言

> **状态：本节已过时（2026-09-26）。** 现行的视觉规范是
> [`../design/mockup.html`](../design/mockup.html)（说明见
> [`../design/README.md`](../design/README.md)）：**同一材质的三档白度 + 34px DWM
> Acrylic + 内顶高光**，主操作为**近黑**而非蓝色。下面这段记录了当时的设想，两者
> 冲突时以 mockup 为准。本文档其余部分（四态交互、信息架构、实施顺序）仍然有效。

- 外层是一片贴近桌面右侧的浅色雾玻璃，使用现有 Tauri/DWM Acrylic 与半透明底色、细内高光、低对比阴影；不要在 CSS 中假称已经模糊桌面。背景效果不可用时降级为不透明、可读的面板。
- 保留 WinIsland 的竖向浮动胶囊和同一容器生长的动势，不复制原型中的空聊天框或装饰性大卡片。面板边角柔和，内部来源行、工具步骤和权限区以紧凑布局和细分隔组织。
- 主体色用冷白/浅灰与深色文字；**主操作近黑**，蓝色只表示焦点，青绿表示运行，琥珀表示等待决策，红色表示失败。主操作色可用户自定义，焦点环不可——两者必须是独立 token，否则把主色改成浅色就会静默破坏焦点可见性。深色模式有独立材料与文字对比，不靠单色蓝紫渐变营造风格。
- 正文与权限内容优先清晰可读；毛玻璃只用在外层和少量非关键浮层。窄栏排版按现有 `20%` 优选、`340–520px` 限宽与长路径/长服务器名设计，不能用视觉留白挤掉决定信息。支持键盘、焦点可见与减少动画偏好。

## 实施顺序与技术门槛

1. **原生可行性。** 在现有 Aside 宿主中验证非激活 Preview 到点击可聚焦 Engaged、点击前目标快照、缩放/点击穿透、窗口恢复。失败就先调整原生窗口方案，不在 CSS 上继续堆界面。
2. **形态与外壳。** 移植 WinIsland 纯状态机思路，接入当前窗口状态；搭出 Collapsed/Preview/Engaged/Pinned 和玻璃材料。保持原生采集与 Node runtime 边界。
3. **完整任务路径。** 迁入聊天、一次性附件、工作目录、工具来源、文档状态和权限决策；逐条覆盖空白、运行、等待、失败、取消、恢复会话和长文本状态。
4. **自动证据与状态记录。** 建前端组件/事件序列测试，验证焦点状态、权限逐次决策、附件到期/清空、覆盖提示和状态投影；跑原有 runtime、Rust、类型和构建门禁。记录人工验收及安装包仍为无限期延后，不把自动通过写成产品验收。

最大工期风险在 WebView2 焦点、透明窗口命中区域、前台快照与窗口恢复，不在配色。先完成第 1 步再估整轮工程量；后续按能演示的一条任务链拆单元，不按「原生/React/Runtime」分大包。
