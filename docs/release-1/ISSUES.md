### R1-06b 结构与权限决策（2026-11-20，用户认可）

记忆（M11）不再是「在平铺会话外建索引」，而是让**项目目录承载会话本身**。以下为已确认的结构与权限约定；实现与此不符即为偏离，须先回到 issue 说明。

| 主题 | 决策 | 理由与代价 |
| --- | --- | --- |
| 结构 | **A：项目目录即会话库**。`<projectsRoot>/<project>/README.md` + `<project>/sessions/--aside-session--/<timestamp>_<id>.jsonl`。不建摘要孪生，不做会话内容的第二份事实。 | 移动会话 = 纯 rename；「继续历史对话」直接打开 JSONL，就是普通会话恢复。代价：会话内容进入用户可见目录，必须靠下面的权限设计补。 |
| 项目根 | 默认 `Documents/Aside/projects`（与默认产物目录同源，用户可带走），并加入 `protectedWorkspacePaths`。 | 默认输出根就是 `Documents/Aside`，不保护等于任何任务都能读整个会话库。 |
| 移动语义 | 会话 header 的 `cwd` 保持常量 `aside-session`，项目只改变文件位置。移动前校验源 / 目标、同 id 冲突、会话是否正在运行；原子 rename；失败保留原位置；**绝不重写内容**。 | 若把 `cwd` 设成项目路径，移动就要改 header，方案不成立。宁可失败也不「修复」文件。 |
| 读权限 | 专用有界接口：项目列表（一句话描述）→ 项目 README → 同项目会话的**有界投影**（复用 04a/06a 的恢复投影）。永不向模型返回原始 JSONL，也读不到项目外的会话。 | 模型能按需读历史，但拿不到文件本身；与「不放开私有会话根」一致。 |
| 写权限 | README 与移动**只在用户触发的整理命令那一次运行中可用**；普通任务对项目目录只读。 | 不靠模型自觉遵守约束，而是按这一次运行的动作集授权。 |
| 归纳触发 | **agent 从不主动归纳 / 分类 / 移动**；新建项目、移动会话、写 README 都由用户命令触发。 | 与 context capture 同一原则：能力可以封装成一次点击，但不能由 agent 自行发起。 |
| 新会话归属 | 默认进入 `inbox` 项目。 | 两层结构不破例；整理命令之后移走。 |
| 冷启动读取 | 两段式：先读所有项目的一句话描述，命中后再读该项目 README，必要时才读历史投影。 | 多项目时不至于一次读进大量文本；与「先小目录再按需」一致。 |
| 旧会话迁移 | 当前处于开发阶段，现有平铺会话视为测试产物，**06b 不做自动迁移**；公开发布前须另定旧库处置（导入 inbox 或明确标为 legacy）。 | 避免为了测试数据引入一次性的迁移逻辑；但这条不能带进发布承诺。 |

**仍待确认**：读取开关的默认值。整理已确定不自动发生，开关实际只管控「任务是否跨会话读取项目内容」；在 06b plan 前需确认默认开还是默认关。
