日期：2026-11-10。里程碑 1；对应验收 H6、H7 / F9。状态：**plan 已写，未开始实现**。只修 [C8-I035 / I038 / I039](../../cycle-8/ISSUES.md) 三项，不扩展其余 P2；当前 WIP 只在 [RECOVERY-PLAN](../../RECOVERY-PLAN.md#2026-11-09-release-1-当前执行表)维护。

## 1. 用户结果与停止线

三项各自独立可复现、独立修复、独立验证，任一项失败不拖累另两项：

1. `mcp.json` 里有无法解析的条目时，在设置里编辑**其他**服务，保存后那条异常配置仍原样留在文件里。
2. 切换会话后，结果区不再显示上一个会话的 documentRead / documentWrite 产物。
3. MCP 新增服务与已有条目同 id 时不会静默覆盖；编辑时改 id 会替换原条目，不留一个暗中仍然启用 / 信任的副本。

停止线：三项各自的复现用例与回归通过，H6 / H7 的自动可验证部分成立。H6 / H7 的实机部分仍归发布收口。

## 3. 输入 / 输出与边界

**I035 的读写契约**：编辑器必须能说清「这条我读得懂」与「这条我读不懂、但文件里有」。读取结果新增一份按原索引排列的异常条目视图；保存时这些条目按原位置原样写回，不参与校验、不被规范化。

这**不**是放宽写入门槛：编辑器自己构造或修改过的条目仍然逐条校验，无效即整次拒绝——现有「an invalid server refuses the whole save」的性质保持不变。区别只在于「用户没碰、编辑器没读懂」的条目不再是编辑器有权删除的对象。

**I038 的投影契约**：会话切换后结果区必须反映新会话的状态。清空发生在 `resetConversationSurface`，因为它是所有「换到另一个会话」路径的唯一收口；不新增第二处清理。

**I039 的编辑语义**：同 id 必须由用户明确选择「覆盖」或「改名」，不接受隐式覆盖；改 id 是替换而非追加，旧条目连同其启用 / 信任状态一并消失。

不做项：不实现 MCP 文件的部分编辑 / 补丁协议；不为异常条目提供 GUI 编辑器（只在界面上明确告知存在几条无法解析、已原样保留）；不改 MCP 的启用 / 信任模型；不顺手修 I036 / I037 / I040。

## 4. 分步实施，串行完成

1. **I035**：`readMcpConfigFile` 返回按索引保留的异常条目；`describeMcpFile` 与 `save_mcp` 接通；`writeMcpConfigFile` 在写回时把它们放回原位置并重新校验它们**没有**被编辑器改动（按原始字节比较，避免把「透传」变成「任意写入」的缺口）。前端在服务器列表上方显示「N 条无法解析的条目已保留」，不显示其内容。
2. **I038**：`resetConversationSurface` 补两处清空；确认 `run_started` 的清理与它不冲突（重复清空是幂等的）。
3. **I039**：`saveDraft` 区分三条路径——新增（id 未出现）、原位编辑（id 未变）、改 id（替换原索引）；新增且 id 已存在时要求明确确认覆盖。

每步先写复现用例，确认它在当前代码上失败，再修，再让它通过。复现失败的记录先保留，不直接改写成通过。

## 5. 失败语义

- 透传条目在传输途中被改动（理论上不可能，按契约实现）：拒绝整次保存并说明，不静默丢弃，不静默写入被改过的内容。
- 文件在编辑器读写之间被外部改动：沿用现有 `mcp_config_conflict` 与 revision 比对，不合并、不猜测。
- 异常条目占满服务数量上限：沿用现有超限拒绝；透传条目与可编辑条目共同计入上限，不因它们是「不可编辑」而绕过计数。
- I039 覆盖后旧条目的分类批准不自动迁移到同 id 的新定义；分类仍按现有 `schema_digest` / `server_fingerprint` 双绑定失效，显式重新批准。
- 会话切换清空是显示层语义：不删除、不修改任何已保存会话与产物；重新打开旧会话时把它们从历史重建，而不是从被清理的内存状态恢复。

## 6. 自动完成条件

| 检查 | 必须证明 |
| --- | --- |
| I035 保留 | 文件含 1 条异常 + 2 条正常条目，只编辑正常条目并保存后，异常条目逐字节不变、仍在原位置；删除一条正常条目后同样成立。 |
| I035 边界 | 编辑器构造的无效条目仍整次拒绝；透传条目在写入前被外部篡改时拒绝；透传条目计入服务数量上限。 |
| I038 清空 | 会话 A 产出 documentRead / documentWrite 后切到会话 B，结果区两者均不显示；切回 A 时从历史重建，不残留错误陈述。 |
| I039 同 id | 新增与已有 id 相同的服务时，未确认不写入；确认后原位替换且不改变顺序。 |
| I039 改 id | 编辑时改 id 后列表条数不变，旧 id 不再存在，旧条目的 enabled / trust 不残留；原 id 的分类不跟随。 |
| 回归 | 既有 MCP 配置 / 运行时 / 会话测试全绿；不因透传而改变运行时加载对同一文件的解读。 |
