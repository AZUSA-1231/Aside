# R1-06a：产物关联与重开定位

日期：2026-11-20。里程碑 1 / M08；对应验收 F9、I3 的产物部分。状态：**plan 已写，未开始实现**。当前 WIP 只在 [RECOVERY-PLAN](../../RECOVERY-PLAN.md#2026-11-09-release-1-当前执行表)维护。

## 1. 用户结果与停止线

重开一个做过文件任务的会话，能看到「哪次执行产出了哪个文件」，并直接打开它或所在文件夹。文件后来被移动或删除时，界面明确说打不开，而不是给一个点了没反应或假装成功的按钮。

停止线：F9 的自动可验证部分成立——两个独立文件任务后重开，产物与各自执行正确对应、可定位；失效路径有明确反馈；历史不串会话。不新建任务管理系统，不做产物版本 / 快照 / 内容预览。

## 2. 已核对的现状与根因

| 事实 | 位置 | 影响 |
| --- | --- | --- |
| 写工具与 DOCX 工具在结果 `details` 中写入 `output_absolute_path`（绝对路径）与 `output_path`（相对路径） | `workspace-write-tools.mjs:589-590`、`docx-tools.mjs:449-450` | 数据已存在，无需新增字段 |
| 运行期已有定位入口 `reveal_existing_path`，路径失效时返回 `path_unavailable` | `src-tauri/src/settings.rs:23-38`、`src/lib/ipc.ts:187` | 可直接复用，不新增命令 |
| 运行期 `tool_result` 事件带 `details`，前端 `writeDocumentStatus` 已能投影产物卡与定位按钮 | `src/lib/document-status.ts:158-179`、`src/App.tsx:1250-1275` | 实时路径已闭环 |
| **04a 的恢复投影只保留 `text` / `status` / `source` / `truncated`，丢弃 `details`** | `agent-runtime/src/session.mjs` 的 `restoreToolCalls` | **这正是本任务的缺口**：重开后产物路径完全丢失 |
| 工作区（workspace）不随会话持久化 | `session.test.mjs` 的「restores no workspace」用例 | **相对路径在重开后无法解析**，只有绝对路径可用 |
| `details` 落盘前经 `boundedToolResult` 投影到约 2 KB 预览并 JSON 解析 | `capability-result.mjs:120-129` | 超限或被截断时可能得不到路径，此时只能如实报告「未记录产物」 |

根因单一：产物引用存在于运行期事件里，但没有进入恢复投影。

## 3. 输入 / 输出与契约

**输入**：已存的 `toolResult` 消息里的 `details`。不新增持久化字段。

**输出**：恢复出的工具调用可携带一个可选的产物引用；界面据此提供「打开 / 显示所在位置」。

提取规则（最小、不猜）：

- 只取 `output_absolute_path`。**不取** `output_path`：它是相对于运行期工作区的路径，而工作区不持久化，重开后拼不出可信的绝对路径。把相对路径当绝对路径用会定位到进程当前目录，那是一个错误的成功。
- 只在调用状态为成功（`succeeded` / `partial`）时提取。失败结果里的路径不是产物，给按钮等于宣称一个没发生的产出。
- 路径必须是绝对路径且不含控制字符，长度设上限。不合规就当作「未记录产物」，不显示按钮。
- 一次调用最多一个产物引用。多个写入的调用各自携带自己的。
- `details` 因截断而无法解析时，不显示产物，也不推断。

定位：复用 `reveal_existing_path`。失败时把 `path_unavailable` 如实显示给用户（「文件已移动或删除」），不静默、不重试、不尝试模糊匹配同名文件。

不做：不新建任务 / 产物管理实体，不建立产物索引，不做内容预览、版本历史、去重、目录同步；不改运行期已有的产物卡；不改写工作区恢复行为。

## 4. 分步实施，串行完成

1. **恢复侧提取**：`restoreToolCalls` 从 `details` 提取合规的绝对产物路径，挂在调用上；不改变已有的状态 / 来源 / 截断语义。
2. **契约字段**：`RuntimeHistoryToolCall` 增加可选产物路径；旧数据缺省时一切照旧。
3. **界面投影**：恢复调用列表里有产物时显示「在文件夹中显示」，复用现有 `revealPath`；失败显示明确错误。
4. **回归与证据**：成功、失败、相对路径、截断、失效路径、多产物、旧会话兼容。

## 5. 失败语义

- 文件已被移动或删除：显示「文件已移动或删除」，不重试、不搜索同目录同名文件、不把路径改成别的。
- `details` 缺路径或不可解析：不显示定位入口，界面不声称有产物。
- 相对路径或非绝对路径：同上，视为未记录。
- 失败调用的结果里带路径：不当作产物。
- 定位命令本身失败（权限、资源管理器异常）：如实显示，不影响会话其它状态。
- 恢复仍是只读：不因提取产物而写回会话文件。

## 6. 自动完成条件

| 检查 | 必须证明 |
| --- | --- |
| 产物关联 | 两次独立写入后重开，两个调用各自对应正确产物，不串到另一条 |
| 只认绝对路径 | `output_absolute_path` 被采用；只有 `output_path` 时不显示定位入口 |
| 状态门槛 | 成功调用有产物；失败调用即使 `details` 含路径也不显示 |
| 有界 | 超长 / 含控制字符的路径被拒绝；`details` 截断时不推断 |
| 失效反馈 | 路径不存在时定位失败信息可读，不伪装成功 |
| 兼容 | 无 `details` 的旧会话恢复如常，不报错 |
| 只读 | 重开前后会话文件逐字节不变 |
