# 呼出式全高侧栏：核心交互与视觉决定

状态：**设计已确认，R1 与 R3 动态焦点 Capture 已完成开发实现与自动化检查；真实焦点切换 / 分屏恢复、Acrylic、圆角与阴影尚未做桌面观察。** 本文是当前前端规范，取代紧凑居中窗口、透明分岛与旧胶囊方案。实现与证据见 [FRONTEND-REVIEW.md](../FRONTEND-REVIEW.md)，下一阶段见 [RECOVERY-PLAN.md](../RECOVERY-PLAN.md)。

## 1. 快捷键自动分屏是核心交互

此前误删的功能已在 R1 重建；它是核心交互，不是可选 feature，也不等待 runtime 齐备或外部 agent 接入。开发实现不等于原生桌面闭环已经验收。

| 用户操作 | 必须发生的行为 |
| --- | --- |
| 原应用全屏／最大化使用时，按下 `Ctrl + Alt + A` | 在 Aside 抢占焦点或改变布局之前，记录原窗口及其原始位置、尺寸和最大化等显示状态，并取得该窗口的 context；原应用调整至工作区左侧 80%，Aside 在右侧 20% 全高展开。 |
| 再次按下同一快捷键 | 隐藏 Aside，并恢复本次记录的原窗口及其原始显示状态；原来最大化的窗口恢复最大化，不能只放大到一个相似矩形。任务、草稿、附件与权限状态继续保留。 |

快捷键呼出同时完成上下文取得与自动分屏，不要求用户再进入另一个分屏模式，不增加独立的开启分屏步骤。原窗口身份绑定到本次呼出，不得在收起时把已经取得焦点的 Aside 或另一窗口误认成恢复目标。

所有结束本次侧栏展示的入口应共用布局恢复路径，避免快捷键能恢复、Esc／隐藏按钮／关闭请求却把原应用留在 80% 宽度。Esc 仍先关闭已打开的 JSON 预览，下一次才收起侧栏。隐藏不取消任务，也不在后台任务完成或权限到达时自行重新分屏。

普通窗口、不能调整的宿主、目标关闭、跨屏／DPI、重复快捷键和部分失败，是恢复实现时需要明确的边界；不能用这些边界把核心路径改成仅覆盖在桌面上的窗口。异常或退出后也不能留下未处理的半套布局。

## 2. 全高侧栏与窗口范围

- 呼出界面保留 sidebar 定义，使用目标显示器的可用工作区全高；不采用此前建议的约 560×620 居中窗口。
- 右侧 20% 与左侧 80% 使用同一工作区和互补的占位计算；处理像素取整，避免上下空缺、窗口间缝隙或重叠。当前独立侧栏的 340–520 逻辑像素限宽不等于已实现这一分屏规则，后续需要一起核对。
- 实际原生窗口范围贴合可见底板，不在底板外保留大块透明区域，也不为上下空缺增加装饰填充。
- 平时真正隐藏，没有常驻胶囊、桌面控件或悬停预览。全高描述呼出后的几何，不代表常驻展示。

## 3. 连续 Acrylic 底板与白色实体组件

用户确定的视觉关系是：**完整的 Acrylic 底板像一张浮起的玻璃桌面，不透明白色组件浮在或嵌在底板上。**

| 层次 | 材质与作用 |
| --- | --- |
| 整体底板 | 一整块连续的原生 Acrylic，覆盖侧栏完整表面；外轮廓采用 DWM 原生圆角方向，并协调系统描边与阴影。 |
| 消息气泡、输入、按钮与控件 | 不透明白色实底，承担阅读和交互；整个对话区没有白色大容器，气泡间露出同一块底板。 |
| 层次与状态 | 柔和外阴影表达浮起，适度内阴影表达嵌入；少量高光或发光用于层次、焦点和交互，不让所有组件同时发光。 |

轻盈感来自玻璃底板与白色实体之间的层次、间距和克制的阴影，不依赖降低正文组件的不透明度。2026-10-31 试用后明确：主要组件与消息气泡统一 12px 圆角，上下文、权限、附件、输入沿同一列边界对齐；附件列表项用分隔代替重复白卡片。旧透明分岛与多档半透明组件不再作为本轮规范。

信息组织保留顶部紧凑状态与上下文、中部可滚动对话与任务结果、底部稳定输入和附件区。工具过程、权限、错误、文件路径和验证信息不能在视觉调整中再次缺失，继续对照 [接口展示复查](../FRONTEND-REVIEW.md#3-原生命令到界面的对应)。

## 4. 技术与范围

- 继续使用现有 Tauri / Rust + React / TypeScript，不为本轮材质切换 WPF 或 WinUI。
- Windows 采用原生 Acrylic 与 DWM 圆角方向。`DWMWCP_ROUND` 是偏好，不等于已指定 8px 半径或保证生效；实际四角、描边与阴影仍需核对。
- 实现中可能仍需透明 WebView 来露出原生材质；配置中的 `transparent` 不代表继续采用透明分岛。
- 材质不可用或要求降低透明度时，降级为连续、可读的实底表面。
- macOS 保留相同布局与交互、采用对应原生材质的方向，本轮不启动移植，也不要求跨平台像素一致。
- 不重建胶囊、悬停、原生窗口变形或多个独立浮窗。原生分屏状态与 runtime 文件 workspace 分开，不修改 agent 执行协议来承担桌面布局。
- 后续窗口渲染技术研究由用户在独立项目进行，本项目本轮只完成上述轻量视觉修正，不继续扩展材质或技术栈实验。

## 5. 当前实现与后续执行

R1 已实现完整 placement 快照、后台一次性 capture 完成后自动排列 / 聚焦、同一目标恢复、重复按键取消、共享隐藏与正常退出清理、失败回退及保留恢复快照重试。普通窗口保留原布局；候选目标拒绝调整时回退并明确报告，原生身份失效时不操作替代窗口。

R3 已按 FE-08 增加 Windows 最近外部焦点跟踪：先呼出，再聚焦其他应用 / 文件夹，回到 Aside 点 Capture 时读取那个最新外部目标；点击 Aside 不清掉它。焦点监听只保留最近窗口元数据，内容仍由呼出 / Capture 交互读取，不向 runtime 发送原始焦点事件。不可用目标明确失败，不回退采集旧宿主。原分屏 placement 快照和呼出时的焦点返回目标独立保留，普通窗口也不会因后续 Capture 而改变收起后的焦点返回对象。实现与边界见 [R3 证据](../cycle-6/R3-INTEGRATION.md)。

配置已恢复原生 Acrylic / 系统阴影，DWM 外角与去描边请求保留；旧分岛样式已替换为连续底板和不透明白色组件。材质无法确认或系统关闭透明度时使用连续实底。全高 80/20 按物理工作区互补计算，旧独立侧栏的逻辑限宽已退出呼出布局。

自动证据是 23 项前端、41 项 Rust、独立类型 / 生产构建及四种浏览器尺寸检查，细节见实现复查。下列桌面证据仍未执行：

1. 真实最大化 / 全屏目标反复完成采集→80/20→恢复原 placement；目标拒绝、关闭及失败恢复也需观察。
2. 快照与 context 的实际焦点顺序、Esc / Hide / 关闭请求 / 正常退出的恢复行为。
3. 复杂背景下连续 Acrylic、实白组件、外角、边缘和阴影；系统降级、混合 DPI 与目标最小尺寸。
4. 真实任务隐藏期间继续运行 / 审批 / 完成后的状态连续性。

浏览器实底截图只证明 CSS 与合成事件投影。正常退出有清理路径，强制结束进程不在本轮恢复保证内。R3 增加的焦点状态回归也不代替真实桌面复测。历史人工验收和安装包仍无限期延期；当前下一步为 R4，状态以主计划和原 issue 为准。
