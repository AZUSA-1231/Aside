# Cycle 8 定义草案：可续接的本地上下文

日期：2026-10-31。状态：**需求讨论草案，尚未批准进入实现。** 用户提出可以开始定义新功能周期；本文提供一个可讨论的有限范围，不把建议写成已确认产品决定。当前任务和历史处置仍以 [RECOVERY-PLAN.md](../RECOVERY-PLAN.md) 为总入口；长期方向见 [PRODUCT-DIRECTION.md](../PRODUCT-DIRECTION.md)。

## 1. 为什么可以开始

R1–R4 的有限开发范围已完成，RT-01–11 有当前实现与自动证据，足以进入下一轮需求定义。产品级验收没有因此完成，原生桌面、真实 provider / 文档和安装包等空白继续按原记录保留；定义新周期不要求先撤销整套历史人工验收延期。

下一轮建议把投入转向 context capture 和本地资料的工作连续性。当前系统已有捕获、运行内附件、文件工具和对话恢复，但这些还不等于能独立说明“这次工作用了哪些资料、产物在哪里、下一步是什么”。这正是后续 memory、自整理与可替换 agent 需要复用的基础。

## 2. 建议只验证一个用户结果

> 在当前文件上呼出 Aside，完成一次阅读或总结；保存这次工作的资料引用、产物位置和简短进度。关闭应用后再次回来，可以核对来源并继续，不必重找路径或重述全部背景。

首个候选场景为 **Explorer 中选中的一份文本 / PDF / Word 文档 → 阅读并形成摘要 → 保存产物及工作记录 → 重启后显式继续**。这是待用户实际重复任务校准的例子，不代表三个格式和所有宿主都必须一起扩展。优先复用现有宿主和读写能力，先选一个已有支持的格式跑通。

这里的工作记录独立于 agent 的聊天历史。它可以关联会话，但不会把原生会话、权限和旧工作区状态打包后直接恢复；现有单一活动会话不能被宣传成已经具备任务切换或会话管理。

## 3. 建议范围

| 工作 | 用户能得到什么 | 本轮建议边界 |
| --- | --- | --- |
| 可核对的捕获来源 | 知道读的是哪份材料、来自哪里、何时获取，以及现在是否还有效。 | 完善现有路径 / target 的交接和版本可用性，不新增后台全文采集；焦点监听仍只定位目标。 |
| 本地工作记录与产物关联 | 找得到材料引用、摘要文件和实际产物，不必自己规划一套目录。 | Aside 提供默认本地存储；区分原文件、应用记录、显式快照、产物与可重建索引。原文件保留原位。 |
| 显式保存与继续 | 一次简单操作保存当前工作；重启后可继续同一份工作并看到失效材料。 | v1 先覆盖一个活动工作记录的续接，完整历史库 / 搜索 / 多任务切换单独判断。 |
| 最小任务记忆 | 看得懂目标、已有结果、用户确认的决定及下一步。 | 使用普通文件保存，带来源和时间；模型摘要标为生成内容，可查看、纠正、删除，不自动升格为长期事实。 |

“低配置负担”在本轮指不要求先创建项目、挑选知识库、配置索引或手工指定数据目录。保存范围和继续哪个工作仍需要明确的用户意图；自动全量保存所有捕获不在这份建议中。

## 4. 文件、Skill 与 runtime 的职责

- 资料引用、记录和产物约定采用普通文件及有版本的简单格式；离开 Aside 后仍能阅读和整理。
- Skill 可以指导 agent 如何使用和更新工作笔记；应用负责确定性保存、版本校验、关联和删除。不能只靠提示词保证写入成功或记忆可信。
- 先用现有读写与上下文交接完成基础路径；本轮不把新专属 agent tool、loop hook 或 Pi 内部状态作为唯一依赖。
- 普通文件可读只证明数据可迁移，不等于已经兼容 Codex / Claude Code 的会话、审批或事件。
- 保存引用不授予文件访问权；继续工作时重新验证来源和工作区，所有修改沿用当前逐次权限边界。

## 5. 进入实现前需确定的三件事

| 决定 | 建议起点 | 为什么影响范围 |
| --- | --- | --- |
| 首个真实重复任务 | 先用一份文档的阅读 / 总结 / 继续工作校准。 | 决定优先补文件路径、选区、网页还是产物回看，不能把它们全当作同一阶段。 |
| 资料保留方式 | 默认保存引用和必要工作记录；全文快照单独说明并由用户触发。 | 必须区分临时 capture 与持久资料，不能把现有短期附件直接永久存下。 |
| 记录、原文件与产物的工作区关系 | 先验证应用默认资料区与现有单 workspace 工具边界如何配合，再定目录规范。 | 现有工具受单一根目录约束，应用资料区可能与原文件分离；不能靠跨根权限、隐式拷贝或更改 cwd 解决。 |

还需要明确继续工作时对会话的处理：在当前会话增加一次有界交接，还是需要最小的新会话入口。若依赖新建会话，应将这个具体依赖显式纳入需求；不能顺手展开完整会话管理。

## 6. 候选验收

以下是新功能应证明的结果，尚未执行，也不代替旧周期人工验收：

1. 不配置项目或知识库即可完成首个任务；界面能解释当前材料、工作记录和产物的位置。
2. 保存后关闭应用再打开，能显式继续同一工作，并提供足够的来源和进度；不靠旧窗口句柄或过期附件恢复。
3. 来源修改、移动、删除或不可读时如实报告，不使用旧摘要冒充当前内容，也不静默猜测同名文件。
4. 产物确实落盘且可定位；记录保存失败时保留可用结果并报告失败，不虚报持久化成功。
5. 用户能查看、纠正和删除工作记录；删除记录不会删除用户原文件。未选择保存的临时捕获不因该功能变为默认长期记忆。
6. 用普通文本编辑器可理解记录和资料入口；基本流程不依赖新专属 agent tool。外部 CLI 兼容性另立验证。
7. 用首个真实任务检查所依赖的呼出、切窗后 Capture、隐藏与恢复路径；只记录实际观察，不把局部试用写成整套 Windows 验收。
