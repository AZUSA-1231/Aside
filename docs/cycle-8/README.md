## 1. 本轮要交付的用户结果

> 用户不用编辑环境文件，就能连接一个已支持的 API、选择模型及可用的思考强度；不指定工作文件夹也有默认产物去处；能新建和找回会话，并在界面管理已有类型的 MCP 服务。

这组需求适合作为一个周期，但应按依赖拆成四批，逐批具备可用结果。不能把“基础功能齐备”扩大为复制所有编码 agent 的 shell、浏览器、插件市场、多 agent 或自动化能力。

本轮继续使用 Pi-backed runtime、Tauri/Rust 和 React/TypeScript。设置与历史入口复用现有呼出界面和组件，保留快捷键、全高侧栏、80/20 自动排列和原窗口恢复，不启动窗口材质或技术栈实验。

## 4. 配置文件：需要统一配置，不必采用 TOML

建议采用有 schema 版本的 **`settings.json`**，GUI 与手工编辑读取同一份设置。Codex 使用 TOML，Claude Code 使用 JSON，OpenCode 支持 JSON / JSONC；没有理由为了外观接近 Codex 再引入一种权威配置。参考 R1、R3、R6。

P0 已实现配置存储 / 来源 / 安全投影底座；P1 已实现下面的 API GUI、原生凭据、连接测试与安全重建约定，其余功能按对应计划：

- 普通用户只有一份可写的用户设置。`mcp.json` 初版可保留为明确位置的子配置，由同一设置服务管理，不在两处重复维护服务定义。
- 普通设置建议按“显式环境覆盖 > 用户 settings > 旧 env 配置兼容回退 > 内建默认值”解析；GUI 显示实际值、来源、被覆盖原因，以及已保存 / 待应用状态。首版不增加项目层、profile 和任意 cwd 自动写配置。
- 旧 `.env.local` / `config.env` 可以导入，兼容读取时保留原有查找次序。导入后不继续双写，也不自动删除旧文件；MCP 路径不能因配置来源迁移而悄悄丢失。环境中的旧凭据若仍覆盖设置，需要明确显示原因。
- 保存前校验，写入采用原子替换；无效文件、权限失败或外部修改冲突需要明确报告，不能覆盖为默认值或显示假成功。
- 普通设置拒绝凭据字段，key 按环境 > Windows Credential Manager > 旧 env 读取，只投影“已配置 / 来源 / 存储错误”。P1 已验证独立临时凭据的系统 API 往返，打包验证仍未执行；GUI 输入 key 时短暂持有它，之后只脱敏读回。key 不进入模型上下文、会话、普通设置读回或日志。
- 每个 run 使用固定的有效配置。运行中可保存为待应用，provider / 连接变更在空闲时经安全重建 runtime 应用；思考强度最迟从下一次请求生效。第一版不做任务中途的任意热替换。
- “测试连接”是用户触发的最小真实模型请求，要说明会访问配置的端点、可能产生少量用量。仅 URL 语法正确或 HTTP 可达不能标为模型已可用；保存设置本身不触发测试。

TOML 若后续有明确偏好可以替换序列化格式，不应改变设置服务、schema 或应用语义。第一版不同时支持 JSON、TOML 与 env 三种可写入口。

## 5. 目录：给用户一个默认位置，内部职责分开

建议设置页只突出一个 **Aside 默认工作目录**。首次启动通过系统目录 API 提供例如“用户文档 / Aside”的默认位置，用户可更改；不要求先选一个目录才能开始。不能硬编码用户目录，因为系统文档目录可能已重定向。

| 目录职责 | 初版约定 |
| --- | --- |
| 默认工作目录 | 无显式 workspace 的任务在这里开始；产物可放 `outputs/`，结果显示实际路径并能定位。用户明确选择的 workspace 继续优先，不被默认值静默覆盖。 |
| 未来 memory | 只预留它将与用户工作资料共存的可能性。本轮不创建记忆策略、事实库、自动读取注入、摘要整理或长期事实。 |
| 会话历史 | 保留现有用户数据区 `Aside/sessions` 和 `ASIDE_SESSION_ROOT` 语义。显示、打开有效目录，不要求用户先配置；本轮不自动搬迁现有历史。 |
| 配置、诊断与缓存 | 留在应用数据区，与用户产物分开。日志 / 凭据不能因为默认工作目录成为 workspace 就被工具顺带读取。 |

“临时存储站”是默认落点，不表示产物可以自动删除。初版不自动清理用户产物，删除会话也不删除原文件或产物；导出、迁移历史根目录和清理策略以后单独设计。

**跨目录是 C8.1 的必需验证点，P2 已实施并回归。** 捕获文件只开放自身，捕获目录只开放其树；显式任务 workspace 优先作为输出，否则使用默认根，相对路径属于输出，外部来源使用绝对路径。复用预览、逐次审批和版本验证，不放大到共同上级、不复制原件、不改变 cwd。不增加任意多工作区管理系统。

恢复会话只恢复可续接的聊天记录及必要配置选择，不恢复旧的访问许可或陈旧桌面快照。来源、输出和当前权限在下一次任务重新验证；会话历史不是长期用户记忆。

## 6. 建议分四批执行

下表表示依赖顺序，没有承诺工期。每批完成自己的开发验证，再进入下一批；状态仅在总计划的 C8 项维护。

| 批次 | 必需范围 | 到此为止的边界 |
| --- | --- | --- |
| C8.0 配置底座 | 确定 schema / 用户路径 / 凭据方案 / 优先级 / 旧配置兼容；实现统一读写、校验、脱敏和待应用契约。 | 一份用户设置；不做多 profile、项目层和任意热重载。先完成这一批，避免界面形成第二套配置逻辑。 |
| C8.1 可用的基础设置 | API、provider、Base URL、模型、连接测试、按模型过滤的思考强度、默认工作目录、产物路径与定位；设置失败可恢复。 | 首版保证现有四个 provider 的已支持组合。手工 Model ID 只有在所选协议、必需模型元数据及真实请求验证成立时才开放；任意 provider 注册不在此批。 |
| C8.2 会话管理 | 新建、列表、指定恢复 / 切换、重命名、删除；显示历史路径；稳定保存并在重启后找回。 | 同时只有一个前台活动会话。切换先结束 / 取消当前任务并保存，不能串入迟到事件或旧权限。不做分支、并行任务、全文检索及跨盘迁移。 |
| C8.3 MCP 与诊断 | stdio 服务新增 / 编辑 / 删除、启用、信任、凭据引用、校验、显式连接测试、状态与错误；空闲时应用连接变更。 | 启用不等于信任，发现工具不自动批准分类。显示既有分类及失效原因，允许清除 / 重新复核，保留双绑定及逐次审批；不做远程 HTTP、OAuth、服务市场和完整策略编辑器。 |

设置页面可以分为“模型与 API / 文件与存储 / MCP / 诊断”，会话列表从对话入口进入。优先复用现有组件和宽度、圆角规范；不要求重做所有聊天界面，也不改变呼出窗口样式。

## 7. 本轮验收目标

这些是整轮要落实的用例，整轮尚未验收。P0 底座的已执行开发检查单独见 [P0 记录](./plans/P0-settings-foundation.md#执行记录)，其余不能当成已通过。
1. 无 `.env` 的用户能从 GUI 保存一个支持的 provider / 模型配置；显式测试和实际对话区分显示。无效设置或写入失败保留旧配置，错误 key / 不可达端点有明确诊断且不泄露 key。
2. 重启后恢复设置；环境覆盖与旧配置来源可核对。修改待应用时显示清楚，当前运行不被隐式重置。
3. 未选目录或捕获文件时，任务仍能在默认目录生成一个产物，显示真实位置；目录只读 / 不存在等失败可恢复，不报告假成功。
4. 读取默认目录之外的已捕获文档并输出到默认位置时，来源与写入范围明确，原件未被移动或意外改写，预览 / 审批 / 验证保持有效。
5. 至少两个命名会话可新建、切换、重启恢复；删除历史不删除产物。损坏历史保留可诊断失败，不把另一会话、旧审批或 capture 内容串入当前任务。
6. 切换模型后仅呈现支持的思考档位，出站请求与选项一致；不能支持的值明确禁用，不静默伪装成已应用。
7. 通过 GUI 管理一个 stdio MCP 服务，测试失败与已配置状态区分；配置变化使旧分类绑定失效，停止 / 撤销与现有权限边界仍有效。
8. 原有快捷键呼出 / 隐藏、自动分屏 / 恢复、动态 Capture、流式 / Stop、结果与错误投影保持工作。超出上下文限制时保留历史，提供可理解的失败及新建会话入口。

实现按涉及范围运行配置、会话、协议、权限及前端回归，并执行相关类型 / 构建与 Rust 检查。真实 provider、MCP 和原生窗口路径若没有实测，必须继续标为未验证，fixture 不能替代它们；旧整轮人工与发布延期不因定义 C8 自动撤销。
