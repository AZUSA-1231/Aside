# Aside v1 实机验收表

更新：2026-11-09。状态：**统一实机默认延期，未执行。** 用户已认可五里程碑方向及最小项目记忆纳入首版，本表据 [V1-SCOPE](./V1-SCOPE.md) 定义发布场景，不因此宣称新增功能已实现。

运行方式：在真实 Windows 桌面上逐项执行，记录**实际观察**，不写"通过"。不符合预期即记为发现，先登记到本表下方"发现的缺陷"，再决定是否阻塞 v1。任何一项不得因为自动测试通过而跳过。

执行时机：功能开发阶段不反复要求整套实机；各功能自动回归照常。开发收口后、公开发布前集中执行现行必过项。F9 为基础产物交付；F15–F24 为项目记忆必过项。F1–F8 / F10–F14 保留历史，不直接执行；B7 为扩展观察，H2 默认指令编辑不在本轮必过范围。现行各组仍未实机执行。

### 分层证明与里程碑门禁

| 层级 | 证明什么 | 不能替代什么 |
| --- | --- | --- |
| 功能自动回归 | 配置 / 存储 / 引用、权限与关闭行为、协议形状、取消 / 失败 / 损坏退路 | 固定输出的 faux agent 不能证明真实模型自然语言归属与文件任务质量。 |
| 项目记忆固定用例 | 在同一模型 / 配置下，从新会话无选择地继续旧工作，隔离无关记录并测量读取量 / token / 延迟 | 不是安装、原生快捷键或厂商支持全集验收；不因个别漂亮示例就关闭里程碑 2。 |
| 集中实机 / 分发 | A–J 的现行必过项、干净 Windows 安装与至少一家真实厂商的完整链路 | 自动回归数量、源码阅读、过去的版本证据均不能替代。 |

里程碑 1 对应 B / C / D、H1 / H5–H7 与 F9；里程碑 2 对应 F15–F24；里程碑 3 对应 H3–H5 / I1–I2；里程碑 4 对应 I3–I5 / J；里程碑 5 统一完成现行必过项。开发中只跑必要定向门禁，集中实机仍延期。固定用例真模型验证如未执行，里程碑 2 只能标“自动门禁通过、模型质量待验”，不得记产品线已通过；后续配套开发可继续，不因此伪造完成状态。

固定用例集应在 R1-06c / 06d plan 实现前写定：至少覆盖报价表、软件项目、私人简历三项工作，在明确请求、自然改述、穿插无关任务三个变体中检查续接和隔离，并包括共享桌面 / 多目录、关闭、歧义、失效引用场景。先用合成资料，不放真实个人信息或厂商凭据。记录模型 / 配置 / 提示版本、输入变体、读取来源与大小、自动续接或询问结果；每个失败保留，不只挑成功样例。

固定用例中的明确续接必须找到正确项目与目录，不得要求用户先选择；歧义用例可以询问。关闭后跨会话读取、无关敏感记录注入、越权读写、历史损坏等安全 / 完整性项任一失败不得用平均成功率抵消。重复次数、token / 字节上限及延迟预算在 06c / 06d plan 测量前写定，不在结果出来后改合格线；预算不合理须显式修订并重跑，不能承诺零成本。

**证据纪律**：不记录 API key、文档正文、MCP 原始帧或模型原始响应。只记录形状与结果（例如"显示 3 个工具名"而非工具定义全文）。
