# Aside v1 / Release-1 范围界定

更新：2026-11-09。**用户已认可“Release → 里程碑 → 功能任务”的执行方向：首版包含基础能力与最小项目记忆，按五个里程碑推进。** 本次将范围、当前证据与验收对齐，不开始修改产品代码，不自动提交。代码基线为 bf3f231，已提交的讨论文档基线为 0e8b587；原自动回归数字是历史证据，本轮没有重新执行产品测试。统一实机默认延期至发布收口。

已确认：**首版不做 Agent 创建；会话保存、运行记录与产物入口是基础功能，不称为 memory。** 最小项目记忆纳入首版：逻辑项目文件夹 + 简单 README + 会话 / 目录引用，让 agent 在新请求中找到相关历史与工作目录，而非要求用户手选旧会话。保持机制轻量，复用已有数据与 agent 判断。详细方案仍逐功能先 plan；本轮不冻结字段、私有历史读取接口或 token 数值预算。禁止后台采集个人数据、推断用户画像。

本文是发布范围唯一合同；能力事实与参考来源见 [RELEASE-CAPABILITIES](./RELEASE-CAPABILITIES.md)，执行状态唯一入口仍是 [RECOVERY-PLAN](./RECOVERY-PLAN.md)。R1/R2/R3 在这里是 Release 阶段，不是历史前端恢复工作的 R1–R4。

## 1. 目标与停止线

> Windows 上的轻量呼出式文件 / 文档 agent：一次配置模型后，无须编辑配置文件或反复找路径；能管理本地能力、看懂执行与消耗、回答问题和审批、保存会话并进行有界长对话，通过可读工作记录跨会话继续工作。

首版是 **Minimum Usable Agent Product**，不是通用编码平台，也不是把成熟 harness 的 package 清单全部搬来。现有 capture、来源 / 输出边界和低负担交互保持一等位置；runtime 仍复用 Pi，不迁移到 DSH / Cordis，不为未来多 agent 预建平台。

R1 的停止线是：下列有限模块、五个里程碑与对应必过验收完成，范围内阻断缺陷为零，再集中执行统一实机 / 分发验收。基础线与产品线缺一不可：既能配置 / 执行 / 保存 / 交付，又能在新会话自然继续相关旧工作。**开发完成与可以公开发布是两个状态。** 统一实机延期不阻塞逐功能开发，但不能把未执行变为通过。

## 3. 工作记录与续接的有限定义

2026-11-08 再次澄清：此前把基础记录称为 memory、把“显式选择旧工作”作为替代终点，均不准确。应区分基础交付和可选项目记忆：

| 对象 | 记录什么 | 首版状态 / 边界 |
| --- | --- | --- |
| 会话记录（M07） | 用户在 Aside 中的对话及执行记录，能保存、重开、回看。 | 聊天持久化已实现；工具轨迹另由 M08 补齐，不重做一套会话存储。 |
| 运行记录 / 产物入口（M08） | 哪次执行实际生成 / 修改了什么，结果、位置及所属会话；可打开文件或所在目录。 | 基础功能必做，不是 memory；依据真实执行结果登记，不额外扩展成独立任务管理系统。 |
| 项目归纳索引（M11） | 在会话库外维护逻辑归纳文件夹，关联 session、资料与产物引用。 | 首版最小实现；自动判断归属，不要求用户先维护工作区。详细布局与开关行为在 06b plan 定义。 |
| 项目内历史检索（M11） | 开关开启且匹配项目后，按需取回该项目中与当前任务相关的历史及目录引用，让新会话继续。 | 首版必做；不等于选旧会话，也不是每次灌入整个文件夹；在 06c / 06d plan 定义实现与退路。 |

例如“整理这份简历”之后，保存会话 S、实际产物 B 并提供打开入口，是基础功能。另一天的新会话若启用项目记忆且匹配到同一求职项目，才按需查到相关历史要求和产物引用；不把这次求职中的私人信息带到无关的软件开发任务。用户主动提交的文件可能含个人信息，不能承诺项目记录永远不含个人数据。

### 基础功能与设计边界

- 基础功能保留已有会话库，补运行 / 产物关联与打开入口。不自动移动 / 重命名用户原文件，不要求先建项目才能完成任务。
- 可选项目记忆建议使用可读、可改、可删的普通本地索引，引用既有 session 与文件；不为实现视觉归纳而移动原始 JSONL 或改变会话存储 cwd。
- 项目索引是历史资料的逻辑目录，不是文件执行工作区，也不是新增路径权限；但可以根据它自动找到并选用相关目录，不要求用户每次选择。一个项目可引用多个目录，同一目录可被多个项目引用，不预建复杂关系机制。路径验证与现有权限规则继续生效，不能直接给模型整个私有会话库的文件访问权。
- 检索建议先匹配最小项目描述，再读取项目内相关片段，保留会话来源。项目匹配不等于所有内容都相关；歧义、敏感会话排除、错误归属纠正、开关关闭后的读取行为须在 plan 中定义。
- 删除索引不默认删除会话或产物；失效文件引用应明确报告，不恢复旧许可。
- 上下文只在用户显式操作时采集（快捷键或现有 Capture 入口）；焦点元数据监听不是持续抓取正文。
- 自动保存自己的执行记录，不等于后台收集环境：不扫描未交给任务的目录，不抓取其他应用正文，不在任务外挖掘用户信息。
- 保存记录不等于每次全部发给模型；记忆开关关闭时不跨会话检索。开启后先读简短项目说明，必要时才读相关历史；不预设额外分类 agent、向量库或每轮全量摘要。系统约束与当前对话保留，执行目录可自动路由但不绕过权限。索引、会话和产物删除语义分别说明。

### 范围变更沿革

此前“自动归属移到 R2、R1 先做显式续接”只是助手建议，未获确认。2026-11-09 用户认可最小项目记忆纳入首版、底座够用后优先验证；本次据此列为里程碑 2。复杂归并 / 拆分、后台自整理仍不做；实现前必须有功能 plan。Compaction 是单会话上下文管理，不是跨会话项目记忆。

## 4. R1 明确不做

- 多命名 Agent / 模板、subagent、多 Agent 协作、workflow、独立后台任务队列、定时任务、fork / branch、执行重放。
- Plugin Registry / Marketplace、在线 Skill / Agent Marketplace、可执行第三方插件和自动依赖安装。内部注册工具与本地 skill 材料不在此列。
- 远程 MCP / OAuth、多账户 / 多 provider profile、项目设置层、配置导入导出全集、远程 Runtime / SDK、多用户 / RBAC、多端同步。
- 长期偏好 / 个人画像、向量记忆平台、独立分类 agent、后台周期性整理、后台主动建议或持续 capture；复杂项目归并 / 拆分、批量回溯整理旧会话和复杂项目管理 UI。最小自动归属 / 检索在 M11 内，不在此排除。
- Codex / Claude Code 外部引擎接入、Mac、新窗口 / 材质 / 分岛研究、第一方 Web search、任意 shell / 代码执行。
- OS Sandbox 平台、自动更新、签名分发平台、精确费用对账和云端遥测。路径审批不宣称隔离外部 MCP；未来扩大可执行能力时必须重审安全边界。

这些不做项不自动成为承诺全部实现的 R2/R3；后续候选分组见能力对照第 5 节。

## 6. 防止继续“想到哪做哪”

1. 一份范围合同、一份总执行表、一份能力事实表；具体功能任务各有一个 plan，问题记 [Release-1 ISSUES](./release-1/ISSUES.md)，旧 Cycle issue 只引用原编号，不重复开单。不一次预写所有 plan。
2. WIP 默认一个功能点；严重度 P0/P1 可打断，其他发现先记录归属。每个功能必须对应 Mxx 与所在交付包。
3. 每点先写输入 / 输出、失败语义、不做项和可自动验证的完成条件；实现、回归、更新状态后才进入下一点。具备独立提交边界，提交按用户授权。
4. 新需求要进 R1，必须由用户批准，同时明确替换哪项或接受范围 / 排期增加；不能借“成熟产品有”直接入场。
5. 默认不要求每点重做统一实机；自动门禁照常执行。真机待验与功能未实现分别记，不把测试数量当作产品完成度。
6. 先证明当前 Pi 路径成立；产品管理、工作记录和交互协议保持独立，不复制 DSH 的全插件架构，不预做外部 runtime 集成。
7. 原严重度与发布归属分开：P2 也可能影响首版承诺；只修已列入 R1 的 I035/I038/I039，其余三项接受明确限制、留到 R2。

## 7. 发布判定与历史变更

- **开发就绪**：五个里程碑要求的功能及自动门禁完成，没有未处置的首版阻断缺陷。M11 的确定性行为与真实模型接续质量分别留证；缺真实模型验证时，只能标开发候选，不能宣称产品线已通过。
